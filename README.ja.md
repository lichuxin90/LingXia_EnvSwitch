# 灵匣 · EnvSwitch

1 台のコンピュータでは Node.js / Python / Go / PyPy をそれぞれ 1 つだけインストールしておき、使う場所が必要なバージョンを選ぶようにします。

[简体中文](README.md) | [繁體中文](README.zh-TW.md) | [English](README.en.md) | 日本語

[変更履歴](CHANGELOG.md)　·　問題報告：[https://github.com/lichuxin90/LingXia_EnvSwitch/issues](https://github.com/lichuxin90/LingXia_EnvSwitch/issues)

## なぜ作ったか

Node を 3 つ、Python を 2 つ入れると、コマンドラインで `node -v` がどれを使うかは PATH の順序と運任せになり、
プロジェクトの切り替えには `nvm use`、仮想環境の切り替えには `source` が必要で、AI アシスタントはコードを書くときリポジトリ内の古い説明をなぞるだけでした。

EnvSwitch はそれらを 1 つのグラフィカルインターフェースにまとめます。バージョンは統一したディレクトリ規則で置き、ターミナルではこれまでどおり `node`、`python`、`go` を直接入力し、
起動した瞬間にいるフォルダを見てどのバージョンに引き渡すか決めるのは、フォワーダーファイル（shim）の層です。プロジェクト側で必要なのは `.tool-versions` の 1 行だけ。

## 主な機能

- **バージョン管理**：公式または中国国内ミラーからバージョンを一覧し、圧縮パッケージをダウンロードして SHA256 を検証し、所定の位置に展開します。全工程に進捗表示とキャンセルが付いています。
- **中断からの再開と並列分割**：大きなファイルのダウンロードが中断しても最初からやり直さず、同じパッケージをすでに完全に取得済みなら二度とダウンロードしません。
- **オフラインパッケージの取り込み**：社内ネットワークの端末からコピーしてきた公式の圧縮パッケージを、そのまま管理下のバージョンとしてインストールできます。
- **プロジェクト単位のバージョン**：`.tool-versions` を認識します（asdf と同じ書式で、`node 22.14.0` の 1 行で足ります）。フォルダに入ると自動的に有効になります。
- **グローバル固定**：オンにするとすべてのフォルダで指定したバージョンを使い、プロジェクト内のバージョン宣言は一時的に無効になります。チームで基準を揃えたい場面に適しています。
- **PATH の引き取りとロールバック**：PATH を変更する前に必ずバックアップを取るので、いつでも元に戻せます。管理者権限が必要になるときは昇格を要求します。
- **ターミナル連携**：PowerShell / bash / zsh のログインファイルに管理下のスクリプトを書き込みます。新しく開いたターミナルはすぐコマンド入口を認識し、`cd` のあとは現在のフォルダが使っているバージョンを知らせてくれます。
- **競合検出**：nvm、pyenv、あちこちに散らばった古いインストールを見分け、引き取ることも共存させることもできます。他のソフトのファイルをこっそり削除することはありません。
- **ライフサイクルの通知**：endoflife.date のデータを読み込み、あるバージョンがメンテナンス終了になっていることを教えてくれます。
- **ホームの環境チェック**：1 画面で保存先・コマンド入口・ターミナル連携・バージョン記録の 4 種類の状態を確認でき、自動で直せるものはワンクリックです。
- **AI クライアント対応**：手元のマシンの Claude Code、Codex CLI、Cursor、Qoder などのクライアントをワンクリックで検出し、統一したランタイムの説明をそれぞれのルールファイルに書き込みます。
- **設定のインポート・エクスポート**：マシンを乗り換えるとき、設定一式をそのまま移せます。
- **4 種類の表示言語**：简体中文、繁體中文、English、日本語を用意し、トレイメニューとウィンドウタイトルも一緒に切り替わります。

## 対応しているランタイム

| ランタイム | バージョン取得元 | 説明 |
| :--- | :--- | :--- |
| Node.js | nodejs.org の公式 dist、npmmirror ミラーに切替可 | npm、npx など同梱コマンドのフォワーディングを含む |
| Python | python-build-standalone のリリース成果物 | gh-proxy 系の加速プレフィックス経由でダウンロード可、サブナビゲーションに PyPy を含む |
| Go | go.dev/dl、golang.google.cn に切替可 | gofmt、go vet 系のコマンドのフォワーディングを含む |
| PyPy | downloads.python.org/pypy | Python の配下に置き、加速版として単独で列挙 |

その他の環境も計画中です。

## はじめ方

1. 公式サイトからインストールパッケージをダウンロードし（正式リリース後は GitHub Releases でも取得できます）、インストールして起動します。

2. 初めての起動では、ランタイムを置くフォルダを選びます。既定はプログラムと同じ階層の `envswitch-data` で、
   システムドライブ以外を選ぶこともできます（例 `D:\envswitch-data`）。C ドライブを避けることをおすすめします。1 バージョンで数百 MB になることが珍しくありません。

3. ホームの環境チェックが、コマンド入口が PATH に入っているか、ターミナル連携がオンになっているかを教えてくれ、ワンクリックで処理できるものはそのまま押せます。

4. 「ランタイム」ページでバージョンを選び、インストールを押します。完了したら新しいターミナルを開いて：

   ```powershell
   node -v
   python -V
   go version
   ```

5. プロジェクトでバージョンを決めたいときは、プロジェクトのルートディレクトリに `.tool-versions` を書きます：

   ```text
   node 22.14.0
   python 3.12.11
   ```

   「プロジェクト単位のバージョン固定」ページでこのフォルダを選び、使いたいバージョンの「これに固定」を押しても、効果は同じです。

## コマンドライン

グラフィカルインターフェースとコマンドラインは同じ設定を共有し、フォワーダーファイル自体がコマンドラインツールです：

| コマンド | 役割 |
| :--- | :--- |
| `envswitch-shim` | 現在のフォルダでどのバージョンが使われるかを知らせます。ターミナルのスクリプトから呼ぶのに適しています |
| `envswitch-shim status` | 各ツールの現在のバージョン、有効になった理由、PATH の実際の並び位置を列挙します |
| `envswitch-shim use <工具> [版本]` | 現在のフォルダのバージョンを固定し、`.tool-versions` に書き込みます |
| `envswitch-shim unuse <工具>` | 現在のフォルダ内での、特定のツールの固定を取り消します |
| `envswitch-shim global <工具> <版本>` | グローバル既定バージョンを設定します |
| `envswitch-shim shims sync` | フォワーダーファイルを再生成します |
| `envswitch-shim hooks [on/off]` | ターミナル連携の状態確認、またはオン・オフ |
| `envswitch-shim help` | 完全な使い方 |

`status` の PATH 並び位置は 2 系統に分けて説明します。現在のターミナルの分が、このコマンドが実際にぶつかる順序で、
レジストリの分は、ターミナル連携を使っていない新規ウィンドウがコマンド入口を認識できるかを決めます。

## データの置き場所

```text
envswitch-data/
  installs/     展開済みの各バージョン
  shims/        コマンド入口（node.exe、python.exe などのフォワーダーファイル）
  cache/        ダウンロードキャッシュ
  partial/      ダウンロード途中の一時分割ファイル
  backups/      PATH 変更前のバックアップ
  config/       設定とバージョン記録
  logs/         実行ログ
  tmp/          展開の中間成果物、インストール完了後すぐに消える
```

別の場所に移す場合：設定で保存場所を変更すると、プログラムは exe の隣に数十バイトの誘導ファイル
`envswitch-data.location` を残すだけです。プロセスに環境変数 `ENVSWITCH_HOME` を設定して、直接指定することもできます。
候補位置は「プログラムと同じ階層、その他の非システムドライブ、最後に C ドライブの共有ディレクトリ」の順に並びます。Windows 以外では、プログラムと同じ階層のあとに `~/.envswitch` が来ます。

プラットフォームについて：主に Windows 10/11 で開発と検証を行っています。Linux と macOS のパスおよび PATH の反映（`~/.profile` に管理下の
スニペットを書き、全ユーザーは `/etc/paths.d/` を通す）は実装済みですが、プラットフォームごとの実機確認は済んでいません。差異を見つけたら Issue を立ててください。

## ダウンロード元・ミラー・プロキシ

- すべてのランタイムについて「ダウンロード元」ページで公式または中国国内ミラーを選べます。「手動ミラーのルートアドレス」を入力するとリストより優先されるので、社内ネットワークの私用ミラーに向いています。
- GitHub からしか取れないパッケージ（たとえば Python のスタンドアロンビルド）は加速プレフィックスを付けられます。形は `https://gh-proxy.com/{url}` で、`{url}` に公式の完全なアドレスを入れます。
- 社内のプロキシを経由する場合は設定にプロキシアドレスを入力すると、バージョン一覧の取得もアップデート確認もその設定に従います。
- すべてのダウンロードが完了した後に SHA256 で検証します。検証を通らなければ展開せず、インストール済みのバージョンを上書きすることもしません。

## 表示言語について

画面・トレイメニュー・ウィンドウタイトルは設定の言語（简体中文 / 繁體中文 / English / 日本語、システムに従う選択も可）に追従します。
以下の 2 か所は規約どおり中国語のままにし、翻訳しません：

- コマンドラインとターミナル連携の出力：ターミナルの中のテキストであり、問題調査時にそのまま貼り出してもらう必要があるもの。
- プログラム内部のエラーメッセージにあるファイルパスとコマンド：翻訳すると、かえってディスク上の実物と突き合わせにくくなります。

## 開発

必要環境：Node.js（本プロジェクトは 24 で開発しています）、pnpm、Rust（edition 2024、`rustup` で最新の安定版を入れれば足ります）、Windows ではさらに WebView2 ランタイムが必要です（Win10/11 は通常同梱されています）。

```bash
pnpm install
pnpm stage:shim    # ターミナル転送用の envswitch-shim をビルド（開発にも包装にも必要）
pnpm tauri dev     # 開発実行、フロントエンドは http://localhost:1420
pnpm check         # svelte-check による型チェック
pnpm tauri build   # インストールパッケージを生成
```

リリースは `.github/workflows/release.yml` が担います。`v0.1.0` のようなタグを付けると、3 つのプラットフォーム向けインストールパッケージと Windows のポータブル版が GitHub Release に上がり、本文は `CHANGELOG.md` の該当バージョンから取られます。`pnpm tauri build` はバンドル前に `scripts/stage-shim.mjs` を実行して転送用の `envswitch-shim` をコンパイルし、パッケージに収めます。これが無いとアプリ自体は入っても、ターミナルでの `node` / `python` / `go` は動きません。

技術スタック：Tauri 2 + Svelte 5（runes）+ TypeScript + Tailwind CSS v4 + shadcn/ui 風のコンポーネント層。
ディレクトリの分担：`src/` は画面、`src-tauri/src/core/` はランタイム管理、PATH、ダウンロード、shim など、実際に作業をするモジュールをまとめています。
両者は `src/lib/ipc.ts` に宣言したコマンドでのみ通信します。Rust が返すのは事実だけ（有無、どのディレクトリか、バージョン番号はいくつか）で、
画面のテキストはすべて `src/lib/i18n/` の 4 言語ディレクトリに置いています。

## よくある質問

**バージョンを入れたのに、ターミナルでは以前のものが動く？**
新しいターミナルを開いてからもう一度試してください。それでもだめなら `envswitch-shim status` の「当前终端」の並び位置を見てください。後ろに並んでいると、
システムに既にある同名のコマンドが先に使われます。ホームの環境チェックでそのまま前に動かせます。

**PATH を元に戻したい？**
PATH を書き込む前に元の値を必ず 1 件保存しています。「環境とターミナル」ページの PATH バックアップ一覧で任意の行の「これに戻す」を押すと、その状態に戻せます（戻す前に現在の値をもう 1 回バックアップします）。アンインストールの前にまず戻してから `shims` ディレクトリを削除してください。

**プロジェクト内の `.tool-versions` が効かない？**
グローバル固定がオンになっていないか確認してください。固定が効いている間はプロジェクト側の宣言が一時的に無視され、ホームの環境チェックにその旨が表示されます。

**2 つのバージョンを共存させられる？**
可能です。EnvSwitch は既存の Node/Python を削除せず、管理下のバージョンを前に並べるだけを担当します。
